# Taste

- Before changing code, expects a thorough upfront exploration of the codebase to understand it (structure, data flow, conventions). Confidence: 0.7
- Wants the agent to proactively fix everything it finds broken or poorly done — not just the specific issues the user enumerated. Confidence: 0.7
- Points the agent at architecture/agent docs (e.g. `arch.md`, `AGENTS.md`) as the source of context and expects them to be consulted. Confidence: 0.6
- When debugging third-party integrations (e.g. Clerk), expects the agent to use the installed/available skills for that tool rather than reasoning from scratch. Confidence: 0.65
- Wants bugs fixed at the root cause (e.g. the underlying data persistence/creation path) rather than patched at the surface so the fix unblocks moving on to the next task. Confidence: 0.6
- Expects a written plan for a non-trivial implementation before coding begins. Confidence: 0.7
- Explicitly encourages the agent to ask many clarifying questions up front before proceeding ("ask me bunch of questions to make a really solid plan"). Confidence: 0.8
- Prefers hard separation of concerns between design/UI and backend: when the task is backend work, expects the UI/design left untouched. Confidence: 0.6
- Prefers a clean-slate removal/rebuild ("start from zero") of flawed or unwanted subsystems over patching them in place. Confidence: 0.6
- Preferred web stack for projects: tRPC + Neon Postgres (Drizzle) + Clerk auth + Vercel AI SDK. Confidence: 0.55
- Executes large plans in discrete phases, reviewing the result and giving explicit approval ("Proceed with Phase X") before the next phase begins, rather than one continuous autonomous run. Confidence: 0.7
- Raises issues as a numbered list and expects the agent to track and address every item raised earlier in the session, not just the most recent one. Confidence: 0.6
- Explicitly rejects generic/default treatment of loading, thinking, empty, error and sidebar states, and expects every one of them to be deliberately designed. Confidence: 0.7
- Prefers reusing existing/pre-built UI components (e.g. shadcn CLI registry components like Aceternity) over hand-rolling them. Confidence: 0.55
- Never wants uppercase text-transform anywhere — no all-caps labels, titles, menu items, buttons, or group labels; strip `uppercase`/`tracking-widest`/`tracking-wider` from component base styles. Confidence: 0.9
- Wants everything rounded — dialogs, dropdowns, menus, alerts, buttons, inputs, popovers, sheets, toasts; never `rounded-none`. Confidence: 0.9
- Destructive actions (delete/remove) must use the red/destructive variant, not primary/default. Confidence: 0.85
- Menu items should be grouped under labeled sections so future actions have a home. Confidence: 0.75
- Wants IBM Plex Sans (and IBM Plex Sans Arabic) used for everything — including code blocks, kbd, mono contexts, and menus; no monospace fonts anywhere, even for code. Confidence: 0.85
- Project design rules are stated as global directives to be applied everywhere, including to generated shadcn/ui components (override library defaults rather than accepting them). Confidence: 0.7
- Expects the agent to decide the design/UI approach on its own initiative and deliver a polished result without being guided each time ("First think about the design element you will use and do it polished, I don't have to tell you each time"). Confidence: 0.75
- Prioritizes end-user simplicity: features must stay easy for the end user (e.g. the student) to understand; complexity is something to design away, not ship. Confidence: 0.7
- Often arrives with ideas already in mind and expects the agent to draw them out through targeted questioning rather than assume or decide unilaterally. Confidence: 0.7
- Favors precise, rich data capture and is willing to restructure/extend the database schema to achieve it, rather than settling for a minimal or approximate data model. Confidence: 0.6
- Prefers key first-run flows (e.g. onboarding) as full-page immersive experiences rather than modals, so there's room for richer/gamified interaction. Confidence: 0.6
- Wants gamified, character-driven UI: the AI persona's avatar should be present and actively "talk"/interact with the user (speech bubbles, animated lines, playful progress and celebration) rather than static forms. Confidence: 0.6
- Expects the agent to stop once things are working — dislikes extended deep-dives chasing phantom/uncertain bugs; when the task is effectively done, wrap up with a concise summary and stop rather than continuing to investigate. Confidence: 0.65
